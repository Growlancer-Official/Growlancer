# Growlancer — Forensic Security + Backend/API Audit

**Document type:** Findings-only security audit (no source code was modified).
**Scope:** All Supabase Edge Functions (`supabase/functions/**`, 33 functions + 3 shared modules), the frontend auth/authorization layer (`src/context/AuthContext.tsx`, `src/lib/supabase.ts`), CORS configuration, secret handling, and the auth flows (signup / login / password reset / email verification / 2FA / OAuth / admin).
**Reference recon:** [`docs/AUDIT_ARCHITECTURE_MAP.md`](docs/AUDIT_ARCHITECTURE_MAP.md:1)
**Method:** Static line-by-line reading of implementation files, migration SQL, CI/CD workflows, and `.env*` files. Every finding cites `file:line` evidence or an explicit reasoning chain. Exploit scenarios are traced for: unauthenticated attacker, authenticated normal user (User A vs User B), admin vs non-admin, forged/replayed webhook, and manipulated amount/ID.

---

## Audit limitations (read first)

1. **No live-DB introspection.** All database conclusions are derived from migration SQL in `supabase/migrations/**` as read statically. Actual deployed function bodies, RLS state, and the current value of `kyc_provider_config.mode` were **not** queried. Items marked **[NEEDS DB]** require a live `pg_get_functiondef(...)` / settings read before final severity is fixed.
2. **No runtime testing.** `execute_command` is unavailable in Architect mode, so no function was invoked, no webhook was replayed, and no timing measurement was performed.
3. **Git history not inspectable.** Whether `SUPABASE_SERVICE_ROLE_KEY` was ever committed historically could not be confirmed (`git log -p -- .env.local` not run). See [SEC-009](#p2--medium).
4. **`.gitignore` verified** — `.env`, `.env.local`, `.env.*.local`, `.vercel`, `.freebuff/`, `*.pdf` are all ignored, which materially lowers the severity of local-secret findings.

### Deployment posture (confirmed)

- [`.github/workflows/supabase-deploy.yml`](.github/workflows/supabase-deploy.yml:40): `supabase functions deploy --no-verify-jwt` → the Supabase gateway **does not** verify JWTs. **Every function's own `auth.getUser()` / cron-secret check is the sole authentication boundary.**
- [`.github/workflows/ci.yml`](.github/workflows/ci.yml:72): build uses placeholder `VITE_*` env; **no secret-scanning (gitleaks/trufflehog) step exists** in CI.
