## 0. Method & Evidence Discipline

- **Inputs read:** [`docs/AUDIT_ARCHITECTURE_MAP.md`](docs/AUDIT_ARCHITECTURE_MAP.md:1), [`docs/AUDIT_FINDINGS_BACKEND_SECURITY.md`](docs/AUDIT_FINDINGS_BACKEND_SECURITY.md:1), the full `supabase/migrations/` tree (200+ migrations), and the client upload clients [`src/lib/fileUpload.ts`](src/lib/fileUpload.ts:1), [`src/lib/portfolioImageUpload.ts`](src/lib/portfolioImageUpload.ts:1), [`src/lib/avatarPack.ts`](src/lib/avatarPack.ts:1), [`src/lib/avatarUpload.ts`](src/lib/avatarUpload.ts:1), [`src/lib/supabase.ts`](src/lib/supabase.ts:358).
- **Migration ordering rule applied:** migrations are applied in lexicographic filename order. Where a *later* migration re-creates an object (`CREATE OR REPLACE`), the later body is authoritative and supersedes any earlier fix — this is the single most productive bug class found in this repo.
- **Duplication control:** findings already enumerated in the backend/API audit are not re-listed here; only database/RLS/storage/money ones are.
- **Honesty rule:** every finding below cites `file:line`. Anything that cannot be confirmed from static migration text is deferred to §5 “Needs live-DB introspection” rather than asserted as fact.
- **Reproduce command (PowerShell)** for any line cited:
  ```powershell
  Select-String -Path .\supabase\migrations\*.sql -Pattern "admin_credentials"
  ```
